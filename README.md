## 📖 معرفی پروژه و قابلیت‌ها

وقتی ربات را در تنظیمات تلگرام خود به بخش **Chat Automation** وصل می‌کنید، پیام‌های چت‌های خصوصی شما به ربات هم می‌رسد. ربات پیام را پردازش می‌کند، با هوش مصنوعی پاسخ می‌سازد و به نام حساب شما ارسال می‌کند.

### 💬 پاسخ‌گویی

| قابلیت | توضیح |
|--------|-------|
| 🧠 هوش مصنوعی سازگار با OpenAI | OpenAI، OpenRouter، Groq، Together، Ollama، LM Studio و ... |
| 🖼 تحلیل تصویر | عکس‌هایی که مخاطب می‌فرستد را (با مدل Vision) می‌بیند و درباره‌اش پاسخ می‌دهد |
| 🎙 پیام صوتی | ویس/صدا را با Whisper (یا سرویس سازگار) به متن تبدیل و پاسخ می‌دهد |
| 😀 استیکر و فایل‌های دیگر | استیکر را می‌فهمد؛ برای ویدیو/فایل/موقعیت فقط به مدل خبر می‌دهد که چه چیزی رسیده |
| 🗂 حافظه‌ی مکالمه | چند پیام قبلیِ همان چت (از جمله پاسخ‌های دستی خودتان) در زمینه‌ی مدل است |
| 📚 دانش کسب‌وکار | متن/فایل اطلاعات (قیمت، خدمات، آدرس، سؤال‌های متداول) که ربات از آن به‌عنوان منبع حقیقت استفاده می‌کند |
| 💬 پاسخ‌های سریع | کلمه‌ی کلیدی ← پاسخ ثابت، بدون مصرف AI و فوری |
| ⌨️ تایپ طبیعی | «در حال تایپ...» تا آماده‌شدن پاسخ |
| 🧩 جمع‌کردن پیام‌های پشت‌سرهم (Debounce) | اگر مخاطب چند پیام کوتاه پشت هم بفرستد، ربات صبر می‌کند و **یک پاسخ یک‌جا** می‌دهد |

### 🧑‍💼 کنترل انسانی

| قابلیت | توضیح |
|--------|-------|
| ⏸ توقف خودکار پس از پاسخ دستی | وقتی خودتان در چتی پاسخ می‌دهید، ربات در همان چت چند دقیقه ساکت می‌شود |
| 🙋 تحویل به انسان | اگر مخاطب انسان بخواهد یا موضوع حساس باشد (شکایت، پرداخت، ...)، ربات پیام تحویل می‌فرستد، ساکت می‌شود و **به مدیر اعلان با لینک کاربر می‌دهد** |
| 🕘 ساعت کاری | فقط در ساعت کاری، یا فقط **خارج** از آن (وقتی دور هستید) پاسخ بده؛ با منطقه‌ی زمانی و روزهای دلخواه |
| 🚦 لیست سیاه/سفید | تعیین اینکه ربات به چه کسانی جواب بدهد |
| 🛑 محدودیت نرخ | سقف پیام در ساعت برای هر چت (ضد اسپم) |

### 🛡 پایداری و مدیریت

- **ارائه‌دهنده‌ی پشتیبان (Fallback):** اگر مدل اصلی از کار افتاد یا محدود شد، خودکار سراغ مدل دوم می‌رود.
- **تلاش مجدد هوشمند** با backoff نمایی و رعایت Retry-After؛ اگر مدل تصویر را نپذیرد، بدون تصویر دوباره تلاش می‌کند.
- **آمار:** پاسخ‌ها، خطاها، میانگین تاخیر و مصرف توکن (امروز/کل).
- **خروجی CSV** از لاگ‌ها و **حذف کامل داده‌های یک کاربر** با `/forget`.
- ☁️ آماده‌ی ابر: فقط متغیر محیطی، بدون فایل سشن، مسیر دیتابیس قابل تنظیم، `Dockerfile` و `docker-compose.yml`.
- 🔌 Long Polling: نیازی به دامنه، SSL یا باز کردن پورت نیست.

> ⚠️ **توجه:** پاسخ‌های ربات از طریق اتصال Business **به نام حساب شما** ارسال می‌شود. پیشنهاد می‌شود شفاف بگویید که پاسخ‌ها با دستیار هوشمند تولید می‌شوند.

## 🗂 ساختار فایل‌ها

```
.
├── main.py              # نقطه‌ی ورود
├── bot.py               # اتصال اجزا: Application، هندلرها، چرخه‌ی حیات
├── business.py          # هسته‌ی دستیار: فیلترها، Debounce، AI، تحویل به انسان، ارسال
├── admin.py             # پنل مدیریت (صفحه‌ها، دکمه‌ها، ورودی متنی/فایل)
├── media.py             # تبدیل عکس/صدا/استیکر به ورودی مدل
├── ai_handler.py        # اتصال به AI: چت، Vision، تبدیل صدا، Fallback، تلاش مجدد
├── schedule.py          # منطق ساعت کاری و تحلیل ورودی (بدون وابستگی به تلگرام)
├── services.py          # حالت مشترک (قفل‌ها، صف‌ها، محدودیت نرخ) و توابع کمکی
├── database.py          # لایه‌ی SQLite
├── config.py            # بارگذاری و اعتبارسنجی متغیرهای محیطی
├── requirements.txt     # وابستگی‌ها
├── Dockerfile
├── docker-compose.yml
├── .env.example         # نمونه‌ی تنظیمات
└── README.md
```

## ✅ پیش‌نیازها

| مورد | توضیح |
|------|-------|
| **پایتون 3.10 یا بالاتر** | برای اجرای مستقیم (بدون Docker) |
| **توکن ربات** | از [@BotFather](https://t.me/BotFather) با دستور `/newbot` |
| **Business Mode برای ربات** | در BotFather: `/mybots` ← ربات ← **Bot Settings** ← **Business Mode** ← روشن |
| **اکانت Telegram Premium** | قابلیت Chat Automation فقط برای حساب‌های Premium (صاحب اکانتی که ربات را وصل می‌کند) |
| **کلید API هوش مصنوعی** | از OpenAI یا هر سرویس سازگار. برای مدل‌های محلی هر مقدار دلخواه |
| **مدل Vision** (برای تحلیل تصویر) | مثلاً `gpt-4o-mini`. اگر مدل شما تصویر نمی‌فهمد، `AI_VISION_MODEL` را جدا بدهید یا `VISION_ENABLED=false` |
| **سرویس تبدیل صدا** (برای ویس) | endpoint استاندارد `/audio/transcriptions` (OpenAI یا Groq). همه‌ی سرویس‌ها (مثلاً بعضی روترها) آن را ندارند؛ در آن صورت `TRANSCRIPTION_BASE_URL` و کلید جدا بدهید |
| **شناسه‌ی عددی شما** | از [@userinfobot](https://t.me/userinfobot) برای `ADMIN_IDS` |

## 🛠 راهنمای نصب گام‌به‌گام

### ۱) کلون کردن ریپازیتوری

```bash
git clone https://github.com/<your-username>/telegram-ai-assistant.git
cd telegram-ai-assistant
```

### ۲) ساخت محیط مجازی (venv)

```bash
# Linux / macOS
python3 -m venv venv
source venv/bin/activate

# Windows (PowerShell)
python -m venv venv
venv\Scripts\Activate.ps1
```

### ۳) نصب وابستگی‌ها

```bash
pip install -r requirements.txt
```

### ۴) تنظیم فایل `.env`

```bash
cp .env.example .env        # در ویندوز: copy .env.example .env
```

حداقل سه مقدار الزامی را پر کنید:

```env
BOT_TOKEN=123456:ABC-your-bot-token
ADMIN_IDS=123456789
AI_API_KEY=sk-...
```

### ۵) اجرا

```bash
python main.py
```

در لاگ‌ها چیزی شبیه `Bot started as @your_bot` می‌بینید. اگر هشدار «Business Mode فعال نیست» آمد، مرحله‌ی BotFather را انجام دهید. سپس در تلگرام به ربات `/start` بدهید تا پنل مدیریت باز شود.

## ⚙️ تنظیمات (.env)

فایل [`.env.example`](.env.example) همه‌ی گزینه‌ها را با توضیح دارد. مهم‌ترین‌ها:

| متغیر | الزامی | پیش‌فرض | توضیح |
|-------|:------:|---------|-------|
| `BOT_TOKEN` | ✅ | — | توکن ربات |
| `ADMIN_IDS` | ✅ | — | شناسه‌ی عددی مدیر/مدیران (با کاما) |
| `AI_API_KEY` | ✅ | — | کلید API |
| `AI_BASE_URL` | ❌ | OpenAI | آدرس API سازگار با OpenAI |
| `AI_MODEL` / `AI_VISION_MODEL` | ❌ | `gpt-4o-mini` | مدل متنی / مدل تصویر |
| `AI_FALLBACK_MODEL` (+ `_API_KEY`, `_BASE_URL`) | ❌ | خالی | مدل پشتیبان؛ با پرکردن مدل فعال می‌شود |
| `TRANSCRIPTION_MODEL` (+ `_API_KEY`, `_BASE_URL`, `_LANGUAGE`) | ❌ | `whisper-1` | تبدیل صدا به متن |
| `COOLDOWN_SECONDS` | ❌ | `3` | حداقل فاصله‌ی پاسخ‌ها در هر چت |
| `DEBOUNCE_SECONDS` | ❌ | `2.5` | مهلت جمع‌کردن پیام‌های پشت‌سرهم |
| `HISTORY_SIZE` | ❌ | `12` | تعداد پیام‌های قبلی در زمینه |
| `PAUSE_MINUTES` | ❌ | `60` | سکوت ربات پس از پاسخ دستی/تحویل (۰ = غیرفعال) |
| `RATE_LIMIT_PER_HOUR` | ❌ | `30` | سقف پیام در ساعت برای هر چت |
| `HANDOFF_ENABLED` | ❌ | `true` | تحویل به انسان |
| `SCHEDULE_MODE` / `WORK_START` / `WORK_END` / `WORK_DAYS` / `TIMEZONE` | ❌ | `off` / `09:00` / `18:00` / `mon…fri` / `Asia/Tehran` | ساعت کاری |
| `VISION_ENABLED` / `VOICE_ENABLED` | ❌ | `true` | تحلیل تصویر / تبدیل صدا |
| `DATABASE_PATH` | ❌ | `data/assistant.db` | مسیر SQLite |
| `LOG_MAX_ROWS` | ❌ | `10000` | سقف لاگ نگهداری‌شده |

> 💡 گزینه‌های رفتاری (تاخیر، ساعت کاری، فیلتر، تحویل به انسان، ...) فقط **مقدار اولیه** هستند. پس از اولین اجرا در دیتابیس ذخیره می‌شوند و از پنل مدیریت قابل تغییرند. برای بازگشت به مقدار `.env`، آن تنظیم را از پنل عوض کنید.

## 📲 راهنمای استفاده

### ۱) اتصال ربات به Chat Automation

1. در تلگرام: **Settings** ← **Telegram Business** ← **Chatbots** (در برخی نسخه‌ها «Chat Automation»).
2. نام کاربری ربات را وارد کنید (مثلاً `@my_assistant_bot`).
3. مشخص کنید ربات روی کدام چت‌ها فعال باشد.
4. دسترسی **Reply to messages** را فعال کنید.
5. ذخیره کنید. مدیر یک اعلان «اتصال Business فعال شد» دریافت می‌کند (به شرط اینکه قبلاً `/start` را زده باشد).

### ۲) پنل مدیریت (`/start`)

| دکمه | کاربرد |
|------|--------|
| ✅/⛔ فعال‌سازی | روشن یا خاموش‌کردن کلی پاسخ‌دهی |
| 🧠 پرامپت | ویرایش شخصیت و لحن ربات (مستقیم از چت) یا بازنشانی |
| 📚 دانش کسب‌وکار | جایگزینی/افزودن/پاک‌کردن اطلاعات؛ می‌توانید فایل `.txt` یا `.md` هم آپلود کنید |
| 🕘 ساعت کاری | حالت، ساعت‌ها، روزها، منطقه‌ی زمانی |
| 💬 پاسخ‌های سریع | افزودن/حذف «کلمه‌ی کلیدی ← پاسخ ثابت» |
| 🚦 فیلتر کاربران | خاموش / لیست سیاه / لیست سفید و مدیریت لیست‌ها |
| 🙋 چت‌های ساکت | دیدن چت‌هایی که ربات در آن‌ها ساکت است، از سرگیری یکی/همه، توقف دستی |
| ⚙️ تنظیمات پیشرفته | کلیدهای تصویر/صدا/تحویل به انسان/خوانده‌شدن؛ تاخیر، Debounce، حافظه، مدت سکوت، سقف نرخ، متن تحویل |
| 📊 آمار | پاسخ‌ها، خطاها، تاخیر و توکن (امروز و کل) |
| 📜 لاگ‌ها | آخرین مکالمه‌ها، خروجی CSV، پاک‌کردن |
| 🔗 اتصال‌ها | حساب‌هایی که ربات را وصل کرده‌اند |

دستورها: `/start` (منو)، `/cancel` (لغو ورودی در حال انتظار)، `/forget <شناسه>` (حذف کامل داده‌های یک کاربر).

## 🔍 قابلیت‌های پیشرفته در جزئیات

### توقف خودکار پس از پاسخ دستی
هر پیامی که **خودتان** در یک چت می‌فرستید، در تاریخچه ثبت می‌شود و ربات در آن چت به‌اندازه‌ی «مدت سکوت» (پیش‌فرض ۶۰ دقیقه) ساکت می‌ماند. پیام‌های خودِ ربات با پیام دستی شما اشتباه گرفته نمی‌شود. از «🙋 چت‌های ساکت» می‌توانید زودتر از سرگیری کنید. مقدار ۰ این رفتار را خاموش می‌کند.

### تحویل به انسان
ربات به مدل دستور می‌دهد اگر مخاطب انسان خواست یا موضوع حساس بود، فقط یک نشانه‌ی داخلی برگرداند. آنگاه ربات «متن تحویل» را برای مخاطب می‌فرستد (قابل ویرایش در تنظیمات)، در آن چت ساکت می‌شود و به همه‌ی مدیران پیامی با لینک کاربر و آخرین پیام او می‌فرستد. (اگر `PAUSE_MINUTES=0` باشد، سکوت تحویل ۱۲۰ دقیقه است.)

### Debounce (پیام‌های پشت‌سرهم)
با پیش‌فرض ۲٫۵ ثانیه، ربات تا آرام‌شدن چت صبر می‌کند و همه‌ی پیام‌ها را یک‌جا جواب می‌دهد (سقف انتظار ۱۵ ثانیه). مقدار ۰ آن را خاموش می‌کند.

### ساعت کاری
- **فقط در ساعت کاری:** مناسب پاسخ‌گویی سازمانی.
- **فقط خارج از ساعت کاری:** ربات وقتی شما دور هستید جواب می‌دهد.
- بازه‌ی شبانه (مثل `22:00-06:00`) پشتیبانی می‌شود. روزها را فارسی (`شنبه یکشنبه ...`)، انگلیسی (`mon,tue`) یا `همه` بدهید.

### دانش کسب‌وکار
اطلاعاتی مثل قیمت‌ها و خدمات را بدهید؛ ربات برای سؤال‌های مرتبط فقط از همین متن پاسخ می‌دهد و اگر پاسخ در آن نباشد، حدس نمی‌زند. برای متن‌های بلند از آپلود فایل `.txt/.md` یا «افزودن» استفاده کنید. سقف حجم با `KNOWLEDGE_MAX_CHARS` تنظیم می‌شود. (این متن به هر درخواست اضافه می‌شود؛ هرچه کوتاه‌تر، ارزان‌تر.)

### پاسخ‌های سریع
فرمت: `کلمه۱|کلمه۲ => متن پاسخ`. اگر پیام مخاطب شامل یکی از کلمات باشد، همان پاسخ ثابت بلافاصله و بدون مصرف AI ارسال می‌شود. (مقایسه بدون حساسیت به حروف انگلیسی و با یکسان‌سازی «ی/ک» و نیم‌فاصله است.)

## ☁️ راهنمای استقرار (Deployment)

ربات از Long Polling استفاده می‌کند، پس فقط یک **پردازه‌ی همیشه‌روشن** لازم است. **فقط یک نمونه** از ربات را با یک توکن اجرا کنید (اجرای هم‌زمان دو نمونه خطای `Conflict` می‌دهد).

### روش ۱: Docker (پیشنهادی)

```bash
git clone https://github.com/<your-username>/telegram-ai-assistant.git
cd telegram-ai-assistant
cp .env.example .env && nano .env      # مقادیر را پر کنید

docker build -t telegram-ai-assistant .
docker run -d --name telegram-ai-assistant \
  --restart unless-stopped \
  --env-file .env \
  -v assistant_data:/data \
  telegram-ai-assistant
```

مشاهده‌ی لاگ‌ها: `docker logs -f telegram-ai-assistant`. دیتابیس روی Volume نام‌دار `assistant_data` در `/data` ذخیره می‌شود و با بازسازی کانتینر از بین نمی‌رود.

### روش ۲: Docker Compose

```bash
docker compose up -d --build
docker compose logs -f
```

### روش ۳: سرور لینوکسی (VPS / AWS EC2) با systemd

```bash
sudo apt update && sudo apt install -y python3 python3-venv git
git clone https://github.com/<your-username>/telegram-ai-assistant.git /opt/telegram-ai-assistant
cd /opt/telegram-ai-assistant
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env
```

فایل `/etc/systemd/system/telegram-ai-assistant.service`:

```ini
[Unit]
Description=Telegram AI Assistant
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=/opt/telegram-ai-assistant
ExecStart=/opt/telegram-ai-assistant/venv/bin/python main.py
Restart=always
RestartSec=5
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo chown -R www-data:www-data /opt/telegram-ai-assistant
sudo systemctl daemon-reload
sudo systemctl enable --now telegram-ai-assistant
sudo journalctl -u telegram-ai-assistant -f
```

### روش ۴: Railway / Render و پلتفرم‌های مشابه

- پروژه را از گیت‌هاب متصل کنید؛ پلتفرم `Dockerfile` را تشخیص می‌دهد.
- متغیرهای `BOT_TOKEN`، `ADMIN_IDS`، `AI_API_KEY` و بقیه را در بخش Environment وارد کنید.
- **حتماً یک Volume/Disk پایدار** به مسیر `/data` وصل کنید؛ وگرنه با هر استقرار مجدد، دیتابیس (تنظیمات، دانش و لاگ‌ها) پاک می‌شود.
- در Render نوع سرویس را **Background Worker** انتخاب کنید (ربات پورت HTTP باز نمی‌کند).

## 🧯 عیب‌یابی

| مشکل | راه‌حل |
|------|--------|
| `BOT_TOKEN تنظیم نشده است` | فایل `.env` را بررسی کنید یا متغیر را در پلتفرم تنظیم کنید |
| ربات جواب نمی‌دهد | ۱) اتصال و «Reply to messages» ۲) پاسخ‌دهی «فعال» باشد ۳) ساعت کاری/فیلتر کاربر مانع نباشد ۴) چت در «چت‌های ساکت» نباشد ۵) لاگ‌ها |
| ربات بعد از پاسخ من دیگر جواب نمی‌دهد | رفتار طبیعی «توقف خودکار» است؛ از «چت‌های ساکت» از سر بگیرید یا `PAUSE_MINUTES=0` بگذارید |
| هشدار «Business Mode فعال نیست» | BotFather ← Bot Settings ← Business Mode |
| گزینه‌ی Chatbots در تلگرام نیست | حساب باید Premium و برنامه به‌روز باشد |
| `Conflict: terminated by other getUpdates request` | نمونه‌ی دیگری از ربات با همین توکن اجراست |
| وضعیت `error: HTTP 401` | `AI_API_KEY` اشتباه یا منقضی است |
| وضعیت `error: HTTP 404/400` | `AI_MODEL` یا `AI_BASE_URL` اشتباه است |
| عکس تحلیل نمی‌شود | مدل Vision ندارید؛ `AI_VISION_MODEL` را تنظیم کنید. (در این حالت ربات بدون تصویر جواب می‌دهد) |
| ویس به متن تبدیل نمی‌شود | سرویس شما `/audio/transcriptions` ندارد؛ `TRANSCRIPTION_BASE_URL` و کلید جدا بدهید |
| `ZoneInfoNotFoundError` / منطقه‌ی زمانی نامعتبر | `pip install tzdata` یا نام درست IANA را بدهید (مثل `Asia/Tehran`) |
| تنظیمات بعد از استقرار مجدد پاک می‌شود | Volume پایدار روی `/data` وصل کنید |
| «علامت خوانده‌شد» کار نمی‌کند | به نسخه‌ی جدید `python-telegram-bot` نیاز دارد و ربات باید دسترسی خواندن پیام‌ها را در Chat Automation داشته باشد (بی‌صدا نادیده گرفته می‌شود) |

برای جزئیات بیشتر `LOG_LEVEL=DEBUG` بگذارید.

## 🔐 حریم خصوصی و نکات امنیتی

- **پیام‌های مخاطبان** (متن، و در صورت فعال بودن: **عکس‌ها و فایل‌های صوتی**) برای تولید پاسخ به سرویس هوش مصنوعیِ شما ارسال می‌شود. متن پیام‌ها و پاسخ‌ها در دیتابیس SQLite هم ذخیره می‌شود (عکس و صدا ذخیره نمی‌شود، فقط توصیف/متن آن). مخاطبان را مطلع کنید و قوانین حریم خصوصی محل خود را رعایت کنید. برای خاموش‌کردن: `VISION_ENABLED=false`، `VOICE_ENABLED=false`، `HISTORY_SIZE=0` یا پاک‌کردن لاگ‌ها.
- با `/forget <شناسه>` همه‌ی داده‌های یک کاربر حذف می‌شود.
- «دانش کسب‌وکار» به هر درخواست AI اضافه می‌شود؛ اطلاعات محرمانه (رمز، کلید) در آن ننویسید.
- فایل `.env` و دیتابیس را هرگز منتشر نکنید (در `.gitignore` هستند).
- فقط شناسه‌های `ADMIN_IDS` به پنل دسترسی دارند.
- اگر توکن لو رفت، فوراً در BotFather با `/revoke` توکن جدید بگیرید.
- لاگ‌های httpx (که توکن را نشان می‌دهند) ساکت شده‌اند.
