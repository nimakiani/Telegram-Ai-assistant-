## 1) معرفی پروژه

نسخه‌های قبلی این پروژه روی «Telegram Business» (Chat Automation) و یک ربات ساخته‌شده با BotFather کار می‌کردند که **فقط با اشتراک Premium** در دسترس است. در این نسخه، لایه‌ی ارتباط با تلگرام با کتابخانه‌ی **Telethon** و پروتکل رسمی **MTProto** بازنویسی شده است؛ ولی **موتور هوش مصنوعی، دیتابیس و همه‌ی قابلیت‌ها همان‌ها هستند** و حذف نشده‌اند.

## 2) قابلیت‌ها

**هوش مصنوعی**
- اتصال به OpenAI، OpenRouter، Groq، Ollama و هر API سازگار با OpenAI (آدرس دلخواه)
- انتخاب مدل + **مدل جایگزین** در صورت خرابی مدل اصلی
- حافظه‌ی مکالمه‌ها (تاریخچه‌ی هر گفتگو جداگانه)
- پرامپت اختصاصی و «دانش کسب‌وکار» (متن یا فایل txt/md)
- تحلیل **تصویر** و تبدیل **پیام صوتی به متن**
- پاسخ‌های سریع بر اساس کلمه‌ی کلیدی (بدون مصرف هوش مصنوعی)

**کنترل و ایمنی**
- فقط **گفتگوی خصوصی** (گروه، کانال، ربات و پیام‌های سرویسی نادیده گرفته می‌شوند)
- لیست سیاه / لیست سفید، روشن/خاموش‌کردن کلی و برای هر گفتگو
- ساعات کاری، محدودیت تعداد پاسخ در ساعت، فاصله‌ی زمانی بین پاسخ‌ها، سقف پاسخ‌های پشت‌سرهم
- **تحویل به انسان**: اگر مشتری بخواهد با خودتان صحبت کند، دستیار ساکت می‌شود و در «Saved Messages» به شما خبر می‌دهد
- آمار عملکرد، لاگ مکالمات، خروجی CSV
- دستیار **هرگز خودش به کسی پیام شروع نمی‌کند**؛ فقط به پیام‌های دریافتی پاسخ می‌دهد

> ⚠️ پنل دکمه‌ای قبلی (داخل ربات) در حساب شخصی ممکن نیست؛ همان صفحه‌ها و تنظیمات اکنون با **دستورهای متنی** در «Saved Messages» در دسترس‌اند (بخش ۱۱).
> قابلیت «تبدیل متن به صدا» در نسخه‌ی قبلی وجود نداشت و اضافه نشده است.

## 3) نحوه عملکرد

```
پیام دریافتی ← فیلترها ← (پاسخ سریع؟) ← تبدیل عکس/ویس ← انتظار کوتاه برای پیام‌های پشت‌سرهم
            ← «در حال تایپ…» ← هوش مصنوعی ← بررسی نهایی ← ارسال با حساب شما
```

**وقتی خودتان پیام می‌دهید**
۱. برنامه تشخیص می‌دهد این پیام را خودش نفرستاده؛
۲. پاسخ‌هایی که هنوز ارسال نشده‌اند **لغو** می‌شوند؛
۳. دستیار در همان گفتگو برای مدتی ساکت می‌شود (پیش‌فرض ۶۰ دقیقه؛ قابل تنظیم)؛
۴. بعد از آن خودکار فعال می‌شود، یا با `/ai resume` دستی.
دخالت شما در یک گفتگو روی بقیه‌ی گفتگوها اثری ندارد.

**معماری (برای برنامه‌نویس‌ها)**: تنها ماژولی که به Telethon وابسته است `tglayer/telethon_gateway.py` است؛ رویدادهای خام به ساختارهای استاندارد (`tglayer/models.py`) تبدیل می‌شوند و موتور (`engine.py`) فقط با آن‌ها کار می‌کند.

```
main.py ─ app.py ─ tglayer/ (Telethon ⇄ مدل‌های داخلی)
                 ├ engine.py     هسته‌ی پردازش پیام و دخالت صاحب حساب
                 ├ commands.py   دستورهای /ai در Saved Messages
                 ├ media.py      عکس/ویس ← متن
                 ├ ai_handler.py موتور هوش مصنوعی (بدون تغییر منطق)
                 ├ database.py   SQLite + مهاجرت امن
                 └ setup_wizard.py راه‌اندازی تعاملی فارسی
```

## 4) چرا Premium لازم نیست؟

Telegram Business و ربات‌ها از «Bot API» استفاده می‌کنند و فقط برای حساب‌های Premium قابل اتصال‌اند. این برنامه مثل خود اپ تلگرام، با **MTProto** و به‌عنوان یک «نشست (Session)» از حساب خودتان وارد می‌شود؛ پس همان کاری را می‌کند که شما با یک دستگاه دیگر می‌کنید. ورود با روش رسمی تلگرام (شماره + کد تأیید + رمز دومرحله‌ای) انجام می‌شود و هیچ مکانیزمی برای دور زدن تأیید هویت یا محدودیت‌ها وجود ندارد.

## 5) دریافت API ID و API HASH

تلگرام برای هر برنامه‌ی شخص ثالث یک شناسه‌ی رایگان می‌دهد:

1. مرورگر را باز کنید: <https://my.telegram.org>
2. با شماره‌ی تلگرام خود وارد شوید (کد داخل خود تلگرام می‌آید).
3. روی **API development tools** بزنید.
4. فرم را پر کنید (نام و Short name دلخواه؛ پلتفرم: Desktop) و **Create application** را بزنید.
5. مقدار **App api_id** (عدد) و **App api_hash** (۳۲ نویسه) را نگه دارید؛ راهنمای راه‌اندازی از شما می‌پرسد.

> API HASH مثل رمز است؛ به کسی ندهید.

## 6) نصب در Ubuntu

پروژه را در یک پوشه قرار دهید (مثلاً بعد از استخراج فایل zip) و در ترمینال همان پوشه:

```bash
chmod +x install.sh
./install.sh
```

این یک دستور همه‌چیز را انجام می‌دهد: تشخیص سیستم، بررسی پایتون (۳.۱۰ به بالا)، نصب بسته‌های لازم، ساخت محیط مجازی، نصب کتابخانه‌ها، ساخت پوشه‌ها، ساخت `.env` از `.env.example`، تنظیم مجوزها (۶۰۰)، بررسی صحت نصب و در پایان اجرای راهنمای راه‌اندازی.

- اجرای دوباره‌ی `./install.sh` امن است و تنظیمات، دیتابیس و Session را پاک نمی‌کند.
- فقط نصب بدون راه‌اندازی: `./install.sh --no-setup`
- بدون پرسش (خودکار): `./install.sh --yes`

## 7) ورود به حساب تلگرام

راهنمای مرحله‌به‌مرحله‌ی فارسی بعد از نصب خودکار باز می‌شود. هر وقت خواستید دوباره اجرایش کنید:

```bash
./start.sh --setup
```

مراحل: API ID ← API HASH ← شماره‌ی تلفن (مثل `+989121234567`) ← **کد تأیید** (از داخل خود اپ تلگرام، پیام «Telegram») ← **رمز دومرحله‌ای** (فقط اگر فعال کرده‌اید) ← ذخیره‌ی Session ← انتخاب گفتگوهای مجاز ← انتخاب سرویس هوش مصنوعی ← API Key ← مدل ← آزمایش اتصال ← گزارش.

- Session در `data/session/assistant.session` با دسترسی ۶۰۰ ذخیره می‌شود؛ **با هر بار اجرا نیازی به ورود دوباره نیست**.
- رمزها و کلیدها موقع تایپ دیده نمی‌شوند و در خروجی/لاگ چاپ نمی‌شوند.
- اگر چند بار کد را اشتباه بزنید، تلگرام ممکن است برای مدتی ورود را محدود کند؛ صبر کنید و دوباره تلاش کنید.

## 8) تنظیم هوش مصنوعی

در راهنمای راه‌اندازی، سرویس را انتخاب می‌کنید:

| سرویس | آدرس API | نکته |
|---|---|---|
| OpenAI | (خالی) | تصویر و ویس پشتیبانی می‌شود |
| OpenRouter | `https://openrouter.ai/api/v1` | ویس جداگانه تنظیم شود |
| Groq | `https://api.groq.com/openai/v1` | ویس با Whisper؛ تصویر بسته به مدل |
| Ollama | `http://localhost:11434/v1` | کلید لازم نیست |
| دلخواه | هر آدرس سازگار با OpenAI | |

تغییر تنظیمات بعداً، **بدون ویرایش دستی فایل‌ها**:

```bash
./venv/bin/python main.py --set AI_MODEL=gpt-4o-mini
./venv/bin/python main.py --set AI_FALLBACK_MODEL=gpt-4o-mini
./venv/bin/python main.py --show-config      # نمایش تنظیمات (کلیدها مخفی)
./restart.sh                                  # اعمال تغییر
```

تنظیمات مهم `.env`: `AI_BASE_URL`، `AI_MODEL`، `AI_FALLBACK_MODEL`، `AI_TEMPERATURE`، `AI_MAX_TOKENS`، `HISTORY_SIZE`، `DEBOUNCE_SECONDS`، `PAUSE_MINUTES`، `MAX_MEDIA_MB`، `LOG_LEVEL`. فهرست کامل با توضیح فارسی در `.env.example` است.
تنظیمات رفتاری (مثل پرامپت، ساعت کاری، لیست‌ها) بعد از اولین اجرا در دیتابیس ذخیره می‌شوند و با `/ai` تغییر می‌کنند.

اگر تنظیمی ناقص یا نادرست باشد، برنامه **همه‌ی مشکلات را یک‌جا و با دلیل** می‌گوید (`./status.sh` یا `./venv/bin/python main.py --check`).

## 9) اجرا و توقف

```bash
./start.sh        # اجرا در پس‌زمینه
./status.sh       # وضعیت، تنظیمات، آخرین گزارش‌ها
./status.sh --logs  # دنبال‌کردن زنده‌ی گزارش‌ها
./stop.sh         # توقف تمیز
./restart.sh      # راه‌اندازی مجدد
./start.sh -f     # اجرا در همین ترمینال (Ctrl+C = توقف)
```

> فقط **یک نمونه** می‌تواند با یک Session اجرا شود (قفل خودکار)؛ اجرای هم‌زمان دو نمونه نشست را خراب می‌کند.

## 10) اجرای خودکار (systemd)

سرویس در سطح **کاربر** نصب می‌شود (بدون root):

```bash
./service.sh install     # نصب سرویس
./service.sh start       # شروع
./service.sh enable      # اجرای خودکار هنگام ورود به سیستم
./service.sh boot-on     # (اختیاری) اجرا بعد از بوت، حتی بدون ورود کاربر
./service.sh logs        # گزارش‌ها با journalctl
./service.sh status
./service.sh disable     # غیرفعال‌کردن اجرای خودکار
./service.sh uninstall   # حذف سرویس
```

- در صورت بسته‌شدن ناگهانی، سرویس خودکار دوباره اجرا می‌شود؛ **حداکثر ۵ بار در ۱۰ دقیقه**، تا وارد چرخه‌ی ری‌استارت بی‌پایان نشود.
- اگر مشکل «نیازمند دخالت شما» باشد (تنظیمات ناقص، نشست باطل‌شده، نمونه‌ی دیگر در حال اجرا) ری‌استارت انجام نمی‌شود و دلیلش در گزارش است.
- مشاهده‌ی مستقیم: `journalctl --user -u telegram-ai-assistant -f`

## 11) مدیریت گفتگوها

همه‌ی دستورها را در گفتگوی **Saved Messages** (پیام‌های ذخیره‌شده‌ی خودتان) بنویسید؛ هیچ‌کس جز شما آن را نمی‌بیند. دستور در گفتگو با دیگران اجرا **نمی‌شود**. فهرست کامل: `/ai help`

| کار | دستور |
|---|---|
| وضعیت کلی | `/ai status` |
| روشن / خاموش کل دستیار | `/ai on` ، `/ai off` |
| پرامپت | `/ai prompt show` ، `/ai prompt set …` ، `/ai prompt reset` |
| دانش اختصاصی | `/ai knowledge set …` ، `add …` ، `show` ، `clear` (یا فایل txt/md با کپشن `/ai knowledge set`) |
| لیست سیاه/سفید | `/ai filter off\|black\|white` ، `/ai black add 12345 @user` ، `/ai white list` |
| ساعت کاری | `/ai schedule inside` ، `/ai hours 09:00-18:00` ، `/ai days mon,tue,wed` ، `/ai tz Asia/Tehran` |
| پاسخ سریع | `/ai quick add قیمت\|price => قیمت‌ها در سایت است` ، `/ai quick list` |
| عددها | `/ai set cooldown 3` ، `debounce` ، `history` ، `pause` ، `rate` ، `streak` ، `media` |
| سوییچ‌ها | `/ai toggle vision off` ، `voice` ، `handoff` ، `markread` |
| گفتگوهای اخیر / ساکت‌شده | `/ai chats` ، `/ai paused` |
| ساکت‌کردن / فعال‌سازی دوباره | `/ai pause @user 30` ، `/ai resume @user` ، `/ai resume all` |
| تنظیم یک گفتگو | `/ai chat 12345 off\|on\|default` ، `prompt …` ، `set history 4` ، `info` |
| آمار، لاگ، CSV | `/ai stats` ، `/ai logs 10` ، `/ai csv` |
| حذف اطلاعات یک نفر | `/ai forget 12345` |

هر گفتگو وضعیت مستقل دارد (روشن/خاموش، توقف، تاریخچه، آخرین فعالیت، دستورالعمل و تنظیمات اختصاصی) و داده‌ها با هم ترکیب نمی‌شوند. «گفتگو» یعنی شناسه‌ی عددی یا `@username` (شناسه‌ی افراد در `/ai chats` دیده می‌شود).

**ضداسپم**: فقط پاسخ به پیام دریافتی؛ فاصله‌ی زمانی بین پاسخ‌ها؛ سقف پاسخ در ساعت؛ سقف پاسخ‌های پشت‌سرهم بدون دخالت شما (پیش‌فرض ۲۰، بعد از آن گفتگو موقتاً ساکت و به شما خبر می‌دهد)؛ در `FloodWait` تلگرام حداکثر یک‌بار و فقط برای انتظار کوتاه صبر می‌شود و بعد پاسخ رها می‌شود (بدون تلاش بی‌پایان).

## 12) رفع خطاهای متداول

| پیام / مشکل | راه‌حل |
|---|---|
| `نشست ورود وجود ندارد` / `AuthKeyUnregistered` | `./stop.sh` سپس `./start.sh --setup` (نشست از «Settings ← Devices» بسته شده) |
| `API ID یا API HASH نامعتبر است` | مقدارها را از my.telegram.org دوباره کپی کنید (`./start.sh --setup`) |
| کد تأیید نمی‌رسد | داخل خود اپ تلگرام، گفتگوی «Telegram» را ببینید؛ چند دقیقه صبر و دوباره تلاش کنید |
| `FloodWait` هنگام ورود | تلگرام موقتاً محدودتان کرده؛ همان مقدار ثانیه صبر کنید |
| `نمونه‌ی دیگری در حال اجراست` | `./status.sh`؛ اگر لازم است `./stop.sh` و دوباره `./start.sh` |
| اتصال برقرار نمی‌شود | اینترنت/فیلترشکن/پروکسی را بررسی کنید؛ MTProto باید به سرورهای تلگرام برسد |
| دستیار جواب نمی‌دهد | `/ai status` (روشن؟ ساعت کاری؟ لیست سیاه/سفید؟) و `/ai paused` (ساکت‌شده بعد از دخالت شما؟) |
| بعد از پاسخ دستی من ساکت شد | طبیعی است؛ `/ai resume <گفتگو>` یا انتظار تا پایان زمان توقف |
| خطاهای هوش مصنوعی (`401`, `404 model`) | کلید/آدرس/نام مدل: `./venv/bin/python main.py --set AI_MODEL=…` سپس `./restart.sh` |
| ویس تبدیل نمی‌شود | سرویس شما endpoint تبدیل صدا ندارد؛ `TRANSCRIPTION_*` را در `.env` بدهید یا `/ai toggle voice off` |
| بعد از ری‌استارت دوباره کد می‌خواهد | فایل `data/session/*.session` پاک شده یا مجوزش خراب است؛ `./start.sh --setup` |

گزارش‌ها: `./status.sh --logs` یا فایل `data/logs/assistant.log`. برای جزئیات بیشتر `LOG_LEVEL=DEBUG` بگذارید (اطلاعات حساس همچنان پوشانده می‌شوند).

## 13) پشتیبان‌گیری و بازیابی

**چه چیزی مهم است؟** فقط این‌ها: `.env` (کلیدها) ، `data/assistant.db` (مکالمات و تنظیمات) ، `data/session/` (نشست تلگرام).

```bash
./stop.sh
tar -czf ~/assistant-backup-$(date +%F).tar.gz .env data --exclude=data/tmp --exclude=data/logs
chmod 600 ~/assistant-backup-*.tar.gz
./start.sh
```

**بازیابی** (روی همین یا سیستم دیگر، بعد از `./install.sh --no-setup`):

```bash
./stop.sh
tar -xzf ~/assistant-backup-2026-01-01.tar.gz
chmod 600 .env && chmod 700 data/session
./start.sh
```

- `./update.sh` قبل از هر به‌روزرسانی خودکار در `backups/` پشتیبان می‌گیرد.
- قبل از هر **مهاجرت دیتابیس** هم یک نسخه‌ی کامل در `data/backups/` ساخته می‌شود.
- پشتیبان شامل Session است: مثل رمز حساب با آن رفتار کنید.
- اگر می‌خواهید روی دو سیستم همزمان اجرا کنید، **نمی‌شود** (یک Session = یک نمونه)؛ برای سیستم دوم یک ورود جداگانه انجام دهید و فقط یکی را روشن نگه دارید.

**به‌روزرسانی**: `./update.sh` (با git) یا `./update.sh نسخه-جدید.zip` — تنظیمات، دیتابیس و Session دست‌نخورده می‌مانند.
**حذف**: `./uninstall.sh` — قبل از پاک‌کردن اطلاعات شخصی تأیید صریح می‌گیرد.

## 14) نکات امنیتی

- **Session = کلید ورود به حساب شما.** هر کس فایل `data/session/*.session` را داشته باشد بدون رمز وارد حساب می‌شود. دسترسی آن ۶۰۰ است؛ آن را کپی/منتشر نکنید.
- `.env`، Session و دیتابیس **هرگز نباید وارد Git شوند** (در `.gitignore` هستند). `.env.example` فقط مقدار نمونه دارد.
- کلیدها در کد نیستند و در لاگ/خروجی چاپ نمی‌شوند.
- اگر فکر می‌کنید نشست لو رفته: تلگرام ← Settings ← **Devices** ← نشست «Telegram AI Assistant» را Terminate کنید؛ و رمز دومرحله‌ای را فعال نگه دارید.
- **حریم خصوصی مخاطبان**: متن پیام‌ها (و عکس/ویس) برای تولید پاسخ به سرویس هوش مصنوعی انتخابی شما ارسال می‌شود. برای مکالمات حساس از لیست سیاه، `/ai chat <id> off` یا یک مدل محلی (Ollama) استفاده کنید. مناسب است به مخاطبان بگویید با دستیار هوشمند صحبت می‌کنند.
- حساب شما مسئول رفتار دستیار است. دستیار عمداً فقط پاسخ می‌دهد و پیام انبوه/شروع گفتگو ندارد؛ همین الگو را حفظ کنید تا حساب شما محدود نشود. قوانین تلگرام و قوانین کشور خود را رعایت کنید.
- هنگام نصب هیچ‌جا از `sudo rm -rf` استفاده نمی‌شود و حذف‌ها فقط داخل پوشه‌ی پروژه و با تأیید شما انجام می‌شوند.
- Docker اختیاری است (`Dockerfile` و `docker-compose.yml` موجودند)؛ برای نصب معمولی لازم نیست.
